# Baton Phases 2 to 9 Implementation Plan

> Task-level plan (not step-level) for the remaining phases, executed autonomously in one run.
> Each phase ends with its PRD acceptance tests (prd.md section 18) recorded in `docs/acceptance.md`.

**Spec:** `prd.md`. **Phase 1 plan:** `2026-09-22-phase-1-spine.md` (done, tag `phase-1-spine`).

## Architecture decisions for the remaining phases

- **One edge function `baton`** with internal routing: `/mcp`, `/hooks/:event`, `/gate/:name`, `/gh`, `/work-available`, `/runs/usage`, `/admin/*`, `/health`. Base URL `https://yemmiowsudakdviqqlnt.supabase.co/functions/v1/baton`. `verify_jwt` off: every route authenticates itself (agent bearer token, operator bearer token, or GitHub HMAC).
- **Direct Postgres from the edge function** through the injected `SUPABASE_DB_URL` (confirmed working). The `baton` schema is not exposed through PostgREST; nothing depends on it being exposed. Reads on behalf of an agent run inside a transaction as role `baton_agent` with `baton.agent_id` set, so RLS applies. Mutations go through `security definer` SQL functions that take the agent id the service resolved from the token.
- **All business logic in SQL functions**, each returning `jsonb` `{ok:true,...}` or `{ok:false,error:{code,message,retryable}}`. The edge function is a thin transport. This keeps the node test harness from Phase 1 as the primary test surface.
- **Identity:** tokens are `btn_<40 hex>`; only the sha256 is stored. `baton.agents` (agents) and `baton.operators` (humans, CLI and dashboard). Revocation is `revoked_at`.
- **Token delivery to Claude Code:** the `BATON_TOKEN` and `BATON_URL` environment variables, set by the supervisor daemon per spawn and by `baton env` for interactive use. Plugin `.mcp.json` and hooks reference them with `${VAR}` expansion, so one machine can run several roles.
- **Cost accounting:** hook payloads carry no cost, so the supervisor daemon reads `stream-json` output and posts token usage per turn and final cost to `/runs/usage`; the Phase 1 trigger rolls it onto the task.
- **Artefact validation:** `pg_jsonschema` in the database, schemas stored in `baton.artifact_schemas` and seeded from `packages/schemas/*.json`.
- **Dashboard data path:** Next.js route handlers call `/admin/*` with an operator token from the dashboard's environment, and the page polls every 5 seconds. Supabase Realtime and Supabase Auth are not used because the project is shared with other applications. Deviation from prd.md section 15, recorded.
- **GitHub secrets** (token, webhook secret) live in Supabase Vault (`vault.create_secret`) and are read by the edge function. Without a token the outbound calls are skipped and logged; inbound webhooks still drive the gate.
