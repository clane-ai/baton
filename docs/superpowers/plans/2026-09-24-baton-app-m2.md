# Baton App M2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the human-facing Baton app in `packages/dash` (Inbox, Item, Runs, Documents, Activity, Spend, Operations) to UAT-ready, in the monday.com-style theme signed off in M1.

**Architecture:** Next.js 15 App Router with real routes under a shared left-rail layout; every screen reads the operator API through the existing `/api/*` proxy routes (`lib/baton.ts`) and the workspace through `/api/workspace`; pure logic (grouping, summaries, email parsing, drafts, state tone) lives in `lib/*.ts` and is unit-tested with vitest; components are thin and read those helpers. The old hash-tab `Dashboard` is retired at the end; the operator views move under `/ops/*` unchanged.

**Tech Stack:** Next.js 15.5, React 19, TypeScript strict, `next/font/google` (Figtree, IBM Plex Mono), `lucide-react`, vitest for `lib/`. No UI library.

**Spec:** `docs/superpowers/specs/2026-09-24-baton-app-m1-design.md` (sections 1, 2, 3 revised, 4, 5). Engine shapes: the engine owner's message of 24 Sep 2026, copied into Task 3.

## Global Constraints

- Edit only `packages/dash/**` and `docs/**`. Never engine code, SQL, schemas, CLI, edge function.
- Next.js 15.5.4, React 19.1.1; no UI component library; only `lucide-react` and `vitest` (dev) are added.
- Real data only: fixtures are runs p2p-101..108, 114..116, 121, 122 and the workspace in `BATON_WORKSPACE`. Never seed or invent rows.
- Nothing is faked: a field the engine does not return is absent on screen, not a placeholder value.
- Copy: sentence case, active voice, controls say what happens ("Approve" → "Approved"). No ALL-CAPS labels.
- Theme tokens (spec §3): canvas `#f6f7fb`, surface `#ffffff`, border `#e6e9ef`, ink `#323338`, ink-2 `#676879`, accent `#6161ff` (hover `#5151d5`, soft `#eeeeff`), done `#00c875`, working `#fdab3d`, stuck `#e2445c`, waiting `#a25ddc`, info `#579bfc`, neutral `#c4c4c4`. Radius 8 px panels, 6 px controls, pills round. Rows 40 px. Base 14 px.
- State → tone, defined once in `lib/theme.ts`: done→done, in_progress/review→working, needs_human→waiting, failed→stuck, blocked→working (tint), ready/draft→info (tint), cancelled→neutral.
- The operator console (Now, Board, Flow, Attention) keeps working at `/ops/*` with no behaviour change.
- Dashboard stays unauthenticated and local; no login.
- Commit after every task with `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

1. An approval whose consumed artefact is missing or malformed (engine summary null): the row must still render with key, title and run, and the item screen must show "No document to show" rather than crash. Test in Task 4 (`summaryLine` with null) and Task 8 (ItemScreen renders with `consumed: []`).
2. A workspace path that does not exist or leaves the workspace: the source tab shows the API's error text and the other tabs still work. Test in Task 6 (`parseEml` on empty input; Sources shows error state).
3. Double-submit of a decision (two clicks on Approve): only one request is sent; the button is disabled while busy and after success. Test in Task 8 (DecisionBar `busy` guard).
4. Reject with an empty reason: blocked in the UI with the message "Add a reason to reject" and never sent (the API route also rejects it). Test in Task 8.
5. An `.eml` with a base64 attachment and quoted-printable body: the pane shows headers, decoded text (soft line breaks joined, `=3D` decoded) and the attachment names, never the base64 blob. Test in Task 6.

```ts
// packages/dash/lib/money.ts
export function money(v: unknown, currency?: unknown): string {
  const n = typeof v === "number" ? v : Number(v);
  if (v === null || v === undefined || v === "" || !Number.isFinite(n)) return "-";
  const s = n.toLocaleString("en-IE", { minimumFractionDigits: 2, maximumFractionDigits: 2 });
  return currency ? `${s} ${String(currency)}` : s;
}
```

- [ ] **Step 3: Implement `lib/inboxFallback.ts`**

```ts
import type { Artifact, InboxItem, InboxSummary, Task } from "./types";
type Obj = Record<string, unknown>;
const o = (v: unknown): Obj => (v && typeof v === "object" && !Array.isArray(v) ? (v as Obj) : {});
export function summaryOf(kind: string, c: unknown): InboxSummary {
  const a = o(c); const pc = o(a.policy_check); const flags: string[] = [];
  if (pc.vendor_approved === false) flags.push("vendor_not_approved");
  if (pc.approver_level === "director" || pc.approver_level === "cfo") flags.push(`level_${pc.approver_level}`);
  if (a.status === "mismatched") flags.push("mismatched");
  if (a.complete === false) flags.push("short_delivery");
  const doc = a.po_number ?? a.invoice_number ?? a.grn_number ?? a.payment_ref ?? a.delivery_note_number ?? null;
  const vendor = o(a.vendor).name ?? a.vendor ?? a.counterparty ?? null;
  const amount = a.total ?? a.amount_payable ?? a.amount ?? null;
  return { document: doc == null ? null : String(doc), counterparty: vendor == null ? null : String(vendor), amount: amount == null ? null : Number(amount), currency: a.currency == null ? null : String(a.currency), flags, produced_by: null, produced_at: null };
}
export function itemFromTask(t: Task, consumed: Artifact[], now: number): InboxItem {
  const primary = consumed.find((a) => a.kind === "purchase_order") ?? consumed[0];
  const summary = primary ? { ...summaryOf(primary.kind, primary.content), produced_at: primary.created_at } : null;
  const kind = t.role === "operator" ? "approval" : "parked";
  const deadline = (t as unknown as { deadline?: string | null }).deadline ?? null;
  return { id: t.id, key: t.key, kind, state: t.state, role: t.role, title: t.title, workflow_run: t.workflow_run ?? null, run_name: null, waiting_since: t.updated_at, deadline, overdue: !!deadline && Date.parse(deadline) < now, summary, next: [], attempts: t.attempts, max_attempts: t.max_attempts, cost_usd: t.cost_usd, budget_usd: t.budget_usd };
```
